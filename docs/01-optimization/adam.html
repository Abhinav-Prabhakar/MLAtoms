    01 · Optimization/tier 1/8 variants/source

    Adam

    Intuition #

    Adam gives every coordinate its own learning rate, derived from the history of that coordinate's gradient:

    \[\theta_i \leftarrow \theta_i - \eta\,\frac{\hat m_i}{\sqrt{\hat v_i} + \epsilon}\]

    m is a smoothed gradient (direction), v is a smoothed squared gradient (scale). Dividing by √v makes the step roughly scale-free: a coordinate whose gradients are consistently 100× larger gets a 100× smaller step. In the first steps, where v is tiny, this behaves like sign descent — |Δθ| ≈ η per coordinate — which is why Adam is so forgiving about the initial LR and so bad at actually converging to high precision.

    Variants #

    Variant Change from Adam When it wins
    adam — default for transformers, sparse gradients, fast prototyping
    adamw weight decay applied to θ, not g any regularised transformer; the modern default
    amsgrad denominator uses max(v_t) over time non-stationary objectives; fixes Adam's non-convergence counterexample
    nadam Nesterov-style momentum on m slight speed-up on vision tasks
    adamax v replaced by running `max g
    radam variance rectification, no update while v is unreliable early training, warmup-free recipes
    adan second statistic is (g_t − g_{t−1}), Nesterov update faster convergence at low LR; used in some diffusion code
    eps_inside_sqrt √(v̂ + ε) instead of √v̂ + ε fp16/BF16, and any case where v underflows

    Derivation #

    Why m/√v. With independent coordinates, the natural gradient is H⁻¹g; the diagonal of the Hessian is approximately the second moment of the gradient, E[g_i²]. So m_i/√v_i is diagonal natural gradient descent with a smoothed estimate of the metric. That is the honest justification; "it normalises the gradients" is the intuition.

    Bias correction. With m_0 = v_0 = 0:

    \[m_t = (1-\beta_1)\sum_{k=1}^{t}\beta_1^{t-k}g_k \;\Longrightarrow\; \mathbb{E}[m_t] = (1-\beta_1^t)\,\mathbb{E}[g]\]

    so dividing by 1−β₁ᵗ (and 1−β₂ᵗ) makes the moments unbiased. Without it the first step is smaller by (1−β₁)/√(1−β₂): the demo measures 0.316η instead of η at β = (0.9, 0.999). That factor is also why "Adam needs warmup" is only half true — the bias correction already handles the start; warmup handles the large early variance.

    AMSGrad. Reddi et al. showed a convex problem where Adam's effective learning rate η/√v̂_t increases, which breaks convergence. Replacing v̂_t with v̂_max,t = max_{s≤t} v̂_s makes the rate non-increasing and restores the O(1/√T) bound.

    AdamW. For SGD, g + λθ and the decoupled θ ← θ(1−ηλ) coincide. For Adam they do not, because the decay is divided by √v:

    \[\text{coupled: } \Delta\theta = \eta\,\frac{\hat m + \lambda\theta}{\sqrt{\hat v}+\epsilon}, \qquad \text{decoupled: } \Delta\theta = \eta\,\frac{\hat m}{\sqrt{\hat v}+\epsilon} + \eta\lambda\theta\]

    Coordinates with small v get their weight decay amplified enormously by the coupled form — the reason L2-Adam under-regularises some layers and blows up others. AdamW's fix is one line and is now the default in every transformer training code.

    RAdam. Early on, v̂ is estimated from very few samples, so its reciprocal is biased and unstable. RAdam computes ρ_t = ρ_∞ − 2tβ₂ᵗ/(1−β₂ᵗ) with ρ_∞ = 2/(1−β₂) − 1, the effective number of samples behind v̂, and:

    • if ρ_t ≤ 4 (usually the first ~5 steps): take a plain momentum step, no adaptive scaling;
    • otherwise: scale the adaptive step by r_t = √(((ρ_t−4)(ρ_t−2)ρ_∞)/((ρ_∞−4)(ρ_∞−2)ρ_t)), which → 1 as t → ∞.

    So RAdam is Adam plus a smooth, automatic warmup — no LR schedule needed for stability.

    Adan. The second moment of the gradient measures magnitude but not agreement. Adan instead smooths the difference d_t = g_t − g_{t−1}:

    \[m_t = (1-\beta_1)m_{t-1} + \beta_1 g_t,\quad v_t = (1-\beta_2)v_{t-1} + \beta_2 d_t,\quad n_t = (1-\beta_3)n_{t-1} + \beta_3 d_t^2\]
    \[\theta \leftarrow \theta - \eta\,\frac{\hat m + \beta_2\hat v}{\sqrt{\hat n}+\epsilon}\]

    This is a Nesterov-style acceleration in which the denominator shrinks exactly when the gradient stops changing — i.e. when the iterate is near a stationary point with consistent curvature. The flip side, visible in the demo, is that the stationary error scales with η: n vanishes like d² while m vanishes like d, so the step does not go to zero. Adan wants a decaying LR at the end.

    Code walkthrough #

    All eight variants share one step; the variant decides which statistics are updated and which denominator is used. The denominator is isolated because that is where the numerical bugs live:

        def _denom(self, v, vmax, eps):
        if self.variant == "eps_inside_sqrt":
            return np.sqrt(v + eps)
        if self.variant == "amsgrad":
            return np.sqrt(np.maximum(vmax, v)) + eps
        return np.sqrt(v) + eps

    sqrt(v) + eps is the original form; sqrt(v + eps) is the fp16/BF16 fix. The difference is not cosmetic: when v underflows to zero, the first gives 1/eps (1e8) and the second gives 1/sqrt(eps) (1e4) — a four-orders-of-magnitude difference in the step. The amsgrad branch takes max(vmax, v); vmax is already the running max of vhat, so the extra maximum only matters on the first step, where vmax is zero and v is not.

    The main loop keeps the moments in place:

                m, v = self.m[i], self.v[i]
            m *= self.b1
            m += (1.0 - self.b1) * g

    In-place *= then += is one pass over memory, and m/v are aliases into self.m[i], so the buffers update without a rebind. The weights are Adam's convention: old history gets β₁, the new gradient gets 1−β₁. Adan swaps them (below), which is easy to miss.

    Adamax replaces the second moment with a running max:

                if self.variant == "adamax":
                self.u[i] = np.maximum(self.b2 * self.u[i], np.abs(g))
                p -= (self.lr / (1.0 - self.b1**t)) * m / (self.u[i] + self.eps)
                continue

    u tracks max(β₂u, |g|), the weighted ∞-norm, so the denominator is bounded by the largest gradient ever seen rather than by its RMS. The bias correction is folded into the outer factor lr/(1−β₁ᵗ) instead of being applied to m — algebraically identical, and it keeps the u update free of the t-dependent scale.

    RAdam has two regimes and the boundary is ρ_t = 4:

                    rho_inf = 2.0 / (1.0 - self.b2) - 1.0
                rho_t = rho_inf - 2.0 * t * self.b2**t / (1.0 - self.b2**t)
                if rho_t > 4.0:
                    r = np.sqrt(
                        ((rho_t - 4.0) * (rho_t - 2.0) * rho_inf)
                        / ((rho_inf - 4.0) * (rho_inf - 2.0) * rho_t)
                    )
                    l_t = np.sqrt(1.0 - self.b2**t) / (np.sqrt(v) + self.eps)
                    p -= self.lr * r * l_t * m / (1.0 - self.b1**t)
                else:
                    p -= self.lr * mhat

    ρ_t is the effective sample size behind v̂: at t=1 with β₂=0.999 it is 1, far below 4, so the first step is the plain momentum step lr·mhat — no adaptive denominator at all. That is why radam and adam agree exactly on step one (the demo asserts 0.99 for both) and diverge later. r is a smooth ramp from 0 to 1, so RAdam is "Adam with an automatic warmup", not a different optimiser.

    Nadam folds the lookahead into the numerator:

                    g_eff = self.b1 * mhat + (1.0 - self.b1) * g / (1.0 - self.b1**t)
                vhat = v / (1.0 - self.b2**t)
                p -= self.lr * g_eff / (np.sqrt(vhat) + self.eps)

    β₁·mhat + (1−β₁)·g/(1−β₁ᵗ) is the bias-corrected version of β₁m + (1−β₁)g, i.e. the gradient evaluated one momentum step ahead. The /(1−β₁ᵗ) on the second term is the part that is usually dropped when copying the formula; without it the first step is smaller than lr and the "Nesterov" variant is just Adam.

    adamw is one line, applied before the gradient path:

                if self.variant == "adamw" and self.wd:
                p -= self.lr * self.wd * p  # decoupled: no gradient term

    and the coupled branch is explicitly excluded afterwards:

                if self.wd and self.variant != "adamw":
                g = g + self.wd * p

    That != "adamw" is what stops the decay from being applied twice. With a zero gradient the difference is stark: coupled Adam divides the decay by √v, which after a few zero-gradient steps is tiny, so it barely shrinks; AdamW multiplies by (1−ηλ) every step regardless. The demo's 0.508 vs 0.774 after five steps is that divergence.

    Adan is a separate method because its state is different:

            self.m[i] = (1.0 - self.b1) * self.m[i] + self.b1 * g
        d = g - self.g_prev[i]
        self.v[i] = (1.0 - self.b2) * self.v[i] + self.b2 * d
        self.n[i] = (1.0 - self.b3) * self.n[i] + self.b3 * d * d
        self.g_prev[i] = g

    Note the coefficient order: (1−β)·old + β·new, the reverse of Adam. This is Adan's paper convention, and mixing it with Adam's convention changes the effective horizon from 1/(1−β) to 1/β. g_prev starts at zero, so the first difference is the full gradient; from the second step on, a constant gradient gives d = 0, n decays geometrically, and the step becomes m/√ε-dominated. The demo checks exactly that decay (9.9e-1 → 9.9e-7) because it is the property that forces Adan to use a decaying LR.

    Complexity #

    Time O(P) per step. Memory 3P for Adam (θ, m, v), 4P for AMSGrad (+v_max), 5P for Adan (m, v, n, g_prev). That ratio is why Adan and AMSGrad are rarely used at LLM scale even when they converge faster per step. All variants vectorise to a handful of fused elementwise kernels; on a GPU the memory traffic, not the arithmetic, is the cost.

    Failure modes #

    1. Non-convergence at the end. Adam's step does not vanish as g → 0 (the ε floor and the EMA keep m/√v at O(1)). Use a decaying LR, or switch to SGD+momentum for the last 10% of training.
    2. Coupled weight decay. adam(weight_decay=0.1) is not AdamW and the effect depends on the gradient scale of each layer. Use adamw and tune λ directly.
    3. ε in the wrong place. √v + ε vs √(v + ε): in fp16, v can underflow to 0 and the first form produces a division by ε = 1e-8, i.e. a gigantic step. Post-LN transformers trained in fp16 crashed on exactly this; BF16 plus eps_inside_sqrt is the robust combination.
    4. β₂ too high for small batches. v averages over 1/(1−β₂) = 1000 steps; with 32-sample batches that is 32k examples, which is fine, but with highly non-stationary data it lags. β₂ = 0.95–0.98 is common in RL for this reason.
    5. Bias correction with a resumed checkpoint. t must be restored too; restarting at t=0 reintroduces the transient (usually harmless, occasionally a visible loss spike).

    Applications #

    • Transformers: AdamW, β=(0.9, 0.95), ε=1e-8, decoupled λ=0.1, warmup
      • cosine decay. This is the canonical LLM recipe.
    • Diffusion models: Adam or Adan with β₂=0.999 and a long warmup; the gradient noise is large and the second moment is genuinely informative.
    • Sparse features (recommenders, NLP with rare tokens): Adam-family updates are per-coordinate, so a feature seen once still gets a sensible step — the main reason it beat SGD there.
    • Fine-tuning with tiny data: AdamW + low LR is more robust than SGD, because the per-coordinate scaling is effectively a per-layer LR.
