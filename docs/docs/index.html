    Documents

    How the repository is built, what it promises, and where it is going.

    • ConventionsThe rules below exist so that 250 atoms written over months still read like one person wrote them. They are enforced by review, and partly by uv run python tools/catalog.py check.
    • NotationUsed consistently across every .md in the repository. When an atom needs a symbol outside this table, it defines it locally and says so.
    • RecipesThe repository is organised by algorithm. Work arrives organised by task. This page is the translation layer: start from the problem, get the three atoms that solve it, in the order you should try them.
    • RoadmapThe catalog is fixed; the code arrives in phases. Each phase is independently useful, so the repository never depends on a future phase to make sense.
    • TiersNot every atom deserves the same effort, and a repository that treats them equally ends up with 250 shallow pages. Tiers are a promise about depth and order.
    • The websiteThe repository is the source of truth; the site is a projection of it.
