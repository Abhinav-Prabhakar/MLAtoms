    Normalisation

    Intuition #

    Normalisation removes a degree of freedom you did not want: the scale and offset of each activation. After it, every layer sees inputs with a known mean and variance, so one learning rate works across layers and depth stops multiplying scale error.

    The textbook reason ("internal covariate shift") is largely wrong — Santurkar et al. showed that BN helps even when the input distribution is held fixed. The mechanism that survives scrutiny is conditioning: normalisation makes the loss landscape smoother (smaller Lipschitz constant of the gradients), which permits larger steps. That is why the layer still helps when the statistics are already stable, and why the placement (before or after the residual add) matters more than the variant.

    Variants #

    Variant Statistics over Depends on batch? Use when
    batch batch + spatial, per channel yes CNNs, large batches
    layer all features, per sample no transformers, RNNs, any batch size
    group channel groups + spatial, per sample no detection/segmentation at small batch
    instance spatial, per channel, per sample no style transfer, generative
    rms RMS over features, no centring no LLMs (cheaper than LayerNorm)
    weight_std weight rows no BN-free reparameterisation
    batch_renorm batch, clipped to running stats yes, bounded small/biased batches with BN
    power_norm l_p norm of the vector no very deep nets without BN

    Derivation #

    Batch norm. For a feature j with batch mean μ_j and variance σ_j²:

    \[\hat x_j = \frac{x_j - \mu_j}{\sqrt{\sigma_j^2 + \epsilon}}, \qquad y_j = \gamma_j \hat x_j + \beta_j\]

    γ, β are learned, so the layer can undo the normalisation if that is better — the network chooses its own scale rather than inheriting it from the initialisation. At inference the batch statistics are replaced by running averages; that switch is the source of most BN bugs.

    Layer norm applies the same formula per sample over all features. It commutes with the batch, which is why it is the default in sequence models where batch composition must not leak across examples.

    Group norm reshapes (N, C, H, W) to (N, G, C/G, H, W) and normalises over (C/G, H, W). G=1 is LayerNorm, G=C is InstanceNorm. It exists because BN's batch statistics are unusable at batch size 2 (detection), and LayerNorm loses the channel structure that convolution encodes.

    RMS norm drops the mean:

    \[y = \frac{x}{\sqrt{\frac1d\sum_i x_i^2 + \epsilon}}\cdot\gamma\]

    Two fewer reductions than LayerNorm, no β, and empirically no loss in quality at LLM scale. The reason it works: in a transformer, the mean of a residual stream is carried by the residual path anyway, so re-centring each block is redundant.

    Batch renormalisation. With r = clip(σ_B/σ, 1/r_max, r_max) and d = clip((μ_B − μ)/σ, −d_max, d_max):

    \[y = \frac{x - \mu_B}{\sigma_B}\,r + d\]

    The clip bounds how much a single odd batch can move the activations, which is what lets BN survive small or non-i.i.d. batches.

    Code walkthrough #

    The file is five near-identical forwards, one helper that decides which axes each of them reduces, and _affine. The helper is where the bugs live:

    def _stats_axes(x: np.ndarray, mode: str) -> tuple[int, ...]:
    if x.ndim == 2:
        ...
            return (0,) if mode == "batch" else (1,)
    if x.ndim == 4:
        if mode == "batch":
            return (0, 2, 3)
        if mode == "layer":
            return (1, 2, 3)
        if mode == "instance":
            return (2, 3)

    Batch norm reduces over the batch and the spatial axes but keeps channels, so (0,2,3) on (N,C,H,W). Layer norm keeps only the batch axis. Instance norm keeps both batch and channel. The 2-D branch collapses all three per-sample modes to (1,), which is why the demo can assert group_norm(img, 1) == layer_norm(img) and group_norm(img, 6) == instance_norm(img) on 4-D but the same identities on matrices are trivial. Writing axis=1 by hand instead of calling this helper is the classic shape bug: it normalises channels in one layout and pixels in another, still trains, and just scores worse.

    Every forward then follows the same three lines:

        mu = x.mean(axis=axes, keepdims=True)
    var = x.var(axis=axes, keepdims=True)
    y = (x - mu) / np.sqrt(var + eps)

    keepdims=True is what makes the broadcast back onto x legal, and x.var uses the biased (1/n) estimator — the right one here, because the normalised output must have exactly unit second moment on the same data. Using ddof=1 makes the output variance n/(n−1) and, worse, divides by zero at n=1.

    group_norm is the only one that reshapes:

        shape = (n, groups, c // groups) + x.shape[2:]
    xg = x.reshape(shape)
    axes = tuple(range(2, xg.ndim))  # everything except batch and group index

    The axes start at 2, not 1: after the reshape the layout is (N, G, C/G, H, W), so axis 1 is the group index and must be kept. Reducing over (1, ...) normalises across groups and turns the layer into instance norm plus a permutation — a silent error, because the output shape is still right and the statistics still look plausible. G=1 and G=C are the two cases that catch it, which is why the demo asserts both.

    rms_norm differs from the others in three deliberate ways:

        rms = np.sqrt(np.mean(x * x, axis=-1, keepdims=True) + eps)
    return _affine(x / rms, gamma, None)

    No mean subtraction, eps inside the square root (adding it after would not bound the reciprocal), and no beta. The axis=-1 is right for the transformer layout (B, T, D); it is not interchangeable with _stats_axes, and that is intentional — RMS norm is only ever used over the feature axis.

    _affine exists so that gamma/beta can be passed as (d,) for any layout:

            g = np.asarray(gamma).reshape((1, -1) + (1,) * (y.ndim - 2)) if y.ndim > 2 else gamma

    A (C,) vector must broadcast against (N,C,H,W) as (1,C,1,1). NumPy will happily broadcast (C,) against the last axis instead, so a missing reshape gives a per-pixel affine transform that runs fine. This three-token expression is the difference between channel affine and pixel affine.

    batch_renorm is the only forward with a state argument, and the clip is the point:

        r = np.clip(np.sqrt(var + eps) / np.sqrt(rv + eps), 1.0 / rmax, rmax)
    d = np.clip((mu - rm) / np.sqrt(rv + eps), -dmax, dmax)
    return (x - mu) / np.sqrt(var + eps) * r + d

    With rm, rv equal to the batch statistics, r = 1 and d = 0, so it reduces exactly to batch norm — the demo asserts that identity. When a batch drifts, r shrinks the variance correction and d bounds the mean shift, so no single batch can move the activations by more than dmax standard deviations. Note the bias correction in Ioffe's paper uses the unbiased running variance; the code uses whatever the caller passes, which keeps the identity with batch_norm exact.

    power_norm normalises to a radius, not to one:

        return x / (norm + eps) * x.shape[-1] ** (1.0 / p)

    The target is ‖y‖_p = d^{1/p}, so that a vector with all entries equal to 1 maps to itself. Normalising to radius 1 instead would shrink activations by √d per layer at p=2 — a depth-dependent scale error that looks exactly like a bad initialisation. The demo's p=2, d=9 case expects norm 3.

    Complexity #

    All are O(n·d) — the same order as the layer they follow, with one extra pass over the activations. group adds a reshape; batch adds a synchronisation point across devices (the real cost at scale). Memory: BN stores 2·d running statistics, LayerNorm 2·d parameters; neither stores activations beyond the forward pass.

    Failure modes #

    1. Train/eval mismatch. Using batch statistics at inference (or running statistics during training) changes the function being evaluated. The classic symptom: validation accuracy collapses the moment you stop training.
    2. Batch size 1. BN with n=1 normalises to zero — every activation becomes β. LayerNorm/GroupNorm or batch renorm are the fixes.
    3. Normalising before the residual add. Pre-LN (x + f(LN(x))) trains stably at depth; post-LN (LN(x + f(x))) needs warmup and often diverges at 24+ layers. The variant is identical; the wiring is not.
    4. γ initialised to zero everywhere. Some "zero-init" recipes kill the whole block at step 0. Zero is right only for the last layer of a residual branch.
    5. Normalising the wrong axis. In (N, C, H, W) tensors, axis=1 normalises channels; using the last axis normalises pixels and destroys the image. Shape bugs here are silent — they still train, just worse.

    Applications #

    • Transformers: rms_norm pre-norm, one per sub-layer.
    • CNNs at batch ≥ 32: batch_norm; at batch < 8 (detection, video): group_norm with G=32.
    • GANs and style transfer: instance_norm (it removes content statistics, which is exactly what you want when only style should vary).
    • BN-free residual nets: weight_std on every conv plus scaled_variance init.
