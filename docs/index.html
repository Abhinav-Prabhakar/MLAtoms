    What this is #

    A reference implementation library, not a framework. Each atom is a single Python file you can read in one sitting, next to a Markdown companion that explains the intuition, derives the update rule, names the failure modes and says where the thing is actually the right tool.

    • One file, no framework. import numpy as np and nothing else. No BaseEstimator, no pipelines, no hidden preprocessing.
    • Every variant. attention ships multi-head, MQA, GQA, sliding-window, linear and a tiled flash-style kernel in the same file, behind variant=. The catalog lists 1,300+ named variants across ~250 atoms.
    • Honest documentation. The .md is not a paper summary. It is what you needed the first time you implemented it, including the part that breaks.

    The idea: atoms and variants #

    An atom is an algorithm family: one .py, one .md, one mathematical core.

    00-primitives/
├── activations.py    17 variants, one forward/backward pair
└── activations.md    why GELU ≠ ReLU in one sentence and one integral

    A variant is a named specialisation of that core — a different loss, a different regulariser, a different approximation.

    Attention(variant="gqa", n_heads=32, n_kv_heads=8)
PCA(variant="kernel", kernel="rbf")
SVM(variant="nu", kernel="rbf", C=1.0)

    Variants exist so the repository can be exhaustive without becoming 1,500 micro-files: one place to read the idea, one switch to pick the flavour.

    Quickstart #

    git clone https://github.com/Abhinav-Prabhakar/MLAtoms.git
cd MLAtoms
uv sync

uv run python 00-primitives/activations.py     # run any atom's demo
uv run python tools/catalog.py stats           # what is in here
uv run pytest                                  # catalog invariants

    Every atom runs standalone:

    uv run python 04-trees-and-ensembles/cart.py
uv run python 07-clustering/hdbscan.py
uv run python 21-causality/doubly_robust.py

    Anatomy of an atom #

    Every atom is exactly two files with the same stem.

    name.py — the implementation.

    """Gradient boosting — functional gradient descent with shrinkage.

Chapter:   04-trees-and-ensembles
Companion: gradient_boosting.md
Tier 1 · 7 variants: regression, binary, multiclass, ...
"""

    name.md — the companion, in this order: intuition → variants → derivation → complexity → failure modes → applications → references.

    The .md answers the four questions a competent reader has, in the fewest words that answer them:

    1. What is the one idea?
    2. What exactly is being optimised, and what is the update?
    3. How does it break?
    4. When should I reach for it instead of something else?
